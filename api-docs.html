API pública · solo lectura

Tus fotos,
también como datos

Cada despliegue publica un conjunto de endpoints JSON estáticos con todas las imágenes y sus metadatos. Sin claves, sin cuotas y sin funciones serverless: se sirven desde el CDN.

Cargando endpoints… · Actualizado en cada push

URL base

—

Funciona con cualquier origen: el dominio de Vercel, un dominio propio o localhost:5173. Las rutas empiezan por /datos/ y las imágenes por /fotos/.

¿Por qué /datos y no /api? Vercel reserva la carpeta /api de la raíz para funciones serverless, así que los archivos estáticos que se colocan ahí no se sirven. Con /datos/ los endpoints son archivos JSON normales servidos desde el CDN.

Endpoints

Método Ruta Devuelve
GET /datos/albumes.json Índice: álbumes con su slug, totales y lista de endpoints
GET /datos/fotos.json Todas las fotos con título, álbum, etiquetas, dimensiones y URL de imagen
GET /datos/albumes/<slug>.json Solo las fotos de un álbum, p. ej. /datos/albumes/general.json
GET /fotos/<ruta> El archivo de imagen original (JPG, PNG, WebP, AVIF…)

Consumirlo

JavaScript / React

const base = 'https://tu-dominio.vercel.app';

const { fotos } = await fetch(base + '/datos/fotos.json')
  .then((r) => r.json());

// fotos[0] => { id, titulo, album, imagen, etiquetas, ancho, alto, … }
<img src={base + fotos[0].imagen} alt={fotos[0].titulo} />

Filtrar por álbum o etiqueta

const res = await fetch('/datos/fotos.json');
const { fotos } = await res.json();

const texturas = fotos.filter((f) => f.album === 'Texturas');
const mar     = fotos.filter((f) => f.etiquetas.includes('mar'));
const ultima  = fotos
  .filter((f) => f.fecha)
  .sort((a, b) => b.fecha.localeCompare(a.fecha))[0];

Buenas prácticas

  • Son archivos, no una base de datos. Se regeneran en cada build (npm run build) leyendo lo que haya en fotos/. No hay escritura en caliente.
  • Cachea con criterio. Los JSON se sirven con max-age=0, must-revalidate para que un push se vea al instante; añade tu propia caché si haces muchas peticiones.
  • ¿Necesitas consultas dinámicas? Este API es de solo lectura y no filtra en el servidor: pide fotos.json y filtra en el cliente, o crea una función propia en /api/ (Vercel Functions) si de verdad necesitas cómputo en el servidor.
  • Los metadatos se editan en fotos/info.json. Títulos, descripciones, etiquetas, fechas y orden alimentan directo estos endpoints.
  • CORS abierto. Al ser archivos estáticos servidos por Vercel, cualquier frontend puede hacer fetch de ellos (solo lectura).
  • No hay datos privados. Todo lo publicado aquí es público: no subas fotos que no quieras exponer.
  • Si mueves o renombras una foto, cambia su URL. Usa el id (ruta relativa) como clave estable solo si controlas los renombrados.
